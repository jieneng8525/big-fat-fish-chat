# HTML 代码块「打开」功能说明

## 这个功能做什么

回答里出现 ```` ```html ```` 代码块时，代码块顶栏会多出一个 **「打开」** 按钮。
点击会在新标签页里直接渲染这段 HTML，**不需要先下载**。

技术实现：把代码块内容封装成 Blob URL 在新标签页打开。
不用 `data:text/html` 是因为 Chrome 已禁止顶层导航到 data URL，那样点开会被静默拦截。

## 已知问题：深色模式下可能白底刺眼

**现象**：系统处于深色模式时，点「打开」后新标签页可能是纯白底。

**原因**：这段 HTML 的样式是**模型生成的**，不是本项目写的。

模型生成 HTML 时通常只写 `background: #fff` 或干脆不写背景色，**不会写 `prefers-color-scheme` 媒体查询**。
浏览器在这种页面上默认用白底，于是深色模式下会出现刺眼的纯白页面。

## 为什么本项目不修

三个层面，逐条说明：

**1. 我们改不了模型的输出。**

模型生成什么 HTML 就渲染什么。它写的 `<style>` 里没有跟随系统的声明，我们没有立场去改写它的内容——
那等于替模型「二次创作」，用户看到的已经不是模型给的东西了。

**2. 模型读不到你的系统深浅色。**

DeepSeek 的对话 API 里，模型只能收到我们发过去的文本。**你的操作系统是深色还是浅色，不在传输范围内。**
模型不知道这件事，自然无法为它写适配。

**3. 我们也改不了官方系统提示词。**

`system` 字段由本项目自己发送，理论上可以在里面加一句「用户界面是深色」。
但这**不保证生效**：模型是否照做，取决于它自己，没有任何机制强制。
而且每轮都要多带这句话，是持续成本（token）。

**因此：这是一个模型侧的问题，本项目不做修改。**

> 附：`latest_reminder` 这条路走不通。实测给它的内容加第六段会被服务端拒绝：
> `Invalid 'messages.0.content': unknown platform '中文'` ——
> 该字段格式被严格限定为 `<日期>,<星期>,<地点>,<平台>,<语言>` 五段。

## 唯一可靠的解法（需要的话可另开任务）

**如果确实希望在深色模式下不刺眼，可行方案是：在「打开」时由本项目给内容注入一层兜底样式。**

这么做能生效，但代价是**改写了模型的原意**——模型精心设计的配色可能被弄乱。
这是一个权衡问题，不是技术问题，故未默认启用。

## 与「导出 HTML」的区别

| | 谁来写样式 | 深色模式表现 |
| --- | --- | --- |
| **导出 HTML**（回答下方 ⬇ → 网页） | 本项目代码 | ✅ 已跟随系统 |
| **打开 HTML**（代码块顶栏 → 打开） | **模型生成** | ❌ 可能白底，本说明所述问题 |

两者容易混淆。导出得到的是本项目生成的完整页面，样式由我们控制，所以能跟随系统；
「打开」只是把模型给的那段 HTML 原样渲染出来。
